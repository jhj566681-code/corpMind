# corpMind

**企业售后问题调查与处理 Agent**

corpMind 面向客服与售后人员，结合 RAG、业务工具和有限轮次的 Agent 执行循环，调查订单与物流异常，形成有证据的处理方案，并在人工确认后创建本地售后工单。

> 当前阶段：需求与设计文档初稿，待评审。业务代码、自动测试、模型效果及部署均未完成；下述内容为计划能力。目前没有可运行程序或启动命令。

## 核心场景

> 客户反馈订单显示签收，但本人没有收到。请核查订单与物流记录，查找适用政策，给出处理方案，确认后创建售后工单。

系统需要根据中间查询结果决定继续调查、追问信息、请求人工确认或停止。第一版覆盖签收未收到、运输延迟，以及信息缺失、无权限和查询失败等分支。

## 计划能力

- **任务规划与工具调用**：查询订单、查询物流、检索政策与历史案例，按证据调整后续动作。
- **RAG 证据**：提供可核对的政策原文、版本和位置；业务事实附查询时间及记录版本。
- **工作记忆与上下文**：保存已知事实、证据和待解决问题，支持任务恢复。
- **人工确认与工单**：展示处理方案，用户确认后创建本地工单，重复确认不重复创建。
- **访问控制与可靠性**：后端校验业务组权限，限制工具轮次，处理超时、过期方案与失败恢复。
- **MCP**：将订单、物流只读查询封装成一个本地 MCP 服务，验证与进程内工具的一致性。
- **评测与交付**：比较基础 RAG、固定工具流程和 ReAct Agent，记录质量、耗时与调用用量。

业务数据和政策均为虚构教学样例。第一版不执行真实退款、不联系客户、不接入真实电商平台；多 Agent 协作和模型训练属于后续独立扩展。

## 技术方向

设计初稿采用 Python 3.12、FastAPI、Pydantic、SQLite、NumPy、BM25 与可配置模型适配器；后端验收后使用 Streamlit 构建界面。MCP、测试和部署按里程碑逐步接入。

具体依赖版本与模型可用性在技术验证阶段确认并锁定。当前仓库尚未实现上述技术方案。
