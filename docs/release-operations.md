# corpMind 发布与运维计划

版本：v0.2-draft。日期：2026-10-26。状态：交付计划，未部署、未演练、无运行结果。

## 1. 交付范围与前提

首版只提供本地演示环境：后端、界面、本地MCP服务和持久化数据。Docker Compose编排在实现阶段新增；当前没有Dockerfile、Compose文件、依赖锁或启动命令，不应按本文声称系统可运行。

模型提供商、地域、模型名、SDK和计费方式在技术验证后确认。依赖与镜像按实际验证版本锁定，生产平台适配独立评审。

## 2. 配置清单

| 配置类别 | 需要记录的内容 |
| --- | --- |
| 模型连接 | 生成、向量、重排模型及端点；密钥由环境注入，不写入仓库 |
| 执行限额 | 模型请求、工具尝试、任务累计次数、活动时间、只读重试和上下文预算 |
| 业务与存储 | 数据位置、数据库迁移版本、样例版本、时钟模式、知识与索引指纹 |
| 身份与服务 | 演示账号初始化方式、会话配置、允许访问的地址；不在文档公开可复用真实口令 |
| 成本 | 100元初始试验预算、各模型实际单价、用量统计和未知费用标记 |
| MCP | 启动方式、协议与SDK版本、授权上下文传递、超时及进程内回退配置 |

本地数据库、知识原文、索引、日志与备份需要独立持久化位置；重建容器不得删除数据。预算估算不等于供应商实际账单或绝对支出上限，实际付费试验需核对账户用量。

## 3. 发布检查

1. G0～G3有对应评审和验证记录，需求、设计、OpenAPI及实现一致。
2. 必需自动检查、权限、确认、幂等、故障恢复和引用测试全部通过。
3. 冻结评测达到目标，结果标注真实模型或模拟模式，列出未解决问题。
4. 干净环境安装与启动经过验证，实际命令及版本补入运行说明。
5. 管理员、客服A、客服B的访问范围检查通过；未授权入口不泄露资源。
6. 数据持久化、备份恢复、迁移和回滚在副本环境演练通过。
7. 密钥不在版本库、日志、界面或镜像中，演示资料均为虚构或获准公开。
8. 发布记录包含版本、提交、数据与配置版本、检查结果、限制、备份位置和回滚路径。

所有检查通过后才创建发布版本；文档和代码分支提交不代表已发布。

## 4. 部署与运行验证

实现后按顺序验证配置、数据迁移、身份、模型适配、MCP、后端健康与界面。健康检查区分服务可用、数据库可用和外部模型连接状态，不用付费调用维持日常存活检查。

演示至少执行一次签收调查、多轮澄清、方案确认、工单创建及重复确认；再执行越权和物流超时。界面上的“已创建”必须对应实际持久化工单。

长期任务按数据库状态恢复。服务重启后不自动执行待确认动作；明确显示中断任务，由用户选择恢复或取消。

## 5. 备份、恢复与回滚

- SQLite使用一致性备份机制；不能在服务运行时只复制主文件而忽略未合并的WAL。
- 备份清单包含数据库、知识资料、索引元数据、迁移版本和必要的配置版本；密钥单独管理。
- 恢复到独立副本，检查完整性、外键、用户权限、任务与工单数量、引用和幂等约束，再决定切换。
- 索引可由原文重建，切换模型或维度后不能继续使用不匹配索引。
- 升级前保留可验证备份。若迁移与旧代码不兼容，回滚应恢复匹配的数据副本和代码，而不是仅回退镜像。
- 回滚前后核对已确认方案与实际工单，不通过重新执行任务补齐可能已成功的写入。

## 6. 运行观察与事件处理

按request_id、task_id记录状态、工具、耗时、失败代码、用量和重试次数。模型不可用、工具故障、额度耗尽、索引不匹配和状态中断分别展示，不能统一伪装成“未找到资料”。

日志不记录密钥、完整业务敏感字段或模型私有推理；必要证据按授权保存并展示可见摘要。

发现权限或写入故障时暂停对应能力，保存必要的脱敏证据，修复后执行回归测试。界面和日志不能把修复前失败记录改写为成功。

## 7. 维护与复盘

发布后根据失败案例、用户反馈和费用修订规则、提示词、索引或工具。每次变更记录影响的FR、AC、数据和模型版本，重跑相应测试；涉及行为变化时评审并更新基线。

复盘记录目标、实际结果、失败原因、修复措施、未解决风险与下一版本范围。展示材料只引用已验证能力和实际测量结果。
