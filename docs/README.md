需求基线：v0.2。更新日期：2026-10-26。状态：G0 需求评审已完成；M1-001 离线学习骨架已建立，查询函数待开发者完成，产品闭环未实现。

## 1. 项目基线

- 产品方向：企业售后问题调查与处理 Agent。
- 首版闭环：订单与物流调查 → 政策核对 → 形成方案 → 人工确认 → 创建本地工单。
- 数据条件：单一虚构企业、两个业务组、本地模拟业务数据与政策。
- 开发安排：Python 为主，先后端再前端，按阶段验收推进。
- 当前阶段：G0／M0 需求基线已评审；M1 已进入 M1-001 离线学习准备，M2～M6、G1～G4 未开始。骨架检查与业务验收分开记录，模型、评测及发布未验证。
- 评审依据：[G0 评审记录](g0-review.md)保存用户确认、需求追溯及文档检查结果；当前工作项为 M1-001：最小项目准备与只读工具契约验证。

## 3. 文档与变更规则

1. 业务行为以需求规格为基线，接口和实现必须可追溯到需求编号。
2. 需求评审、技术设计评审和应用验证分别记录；G0 通过不批准全部技术方案。实现偏离基线时，先记录变更影响，经用户确认后同步需求、设计及测试。
3. 使用“计划、已实现、已验证”区分状态。通过状态必须附提交、测试输出或实际操作记录。
4. 不在文档中填写密钥、真实客户信息、伪造实验结果或未验证的性能数字。
5. 每个里程碑提交一个可独立审查的变更，范围和验证方法写入 Pull Request。
6. 新增 SDK、模型或基础设施前，确认当前官方文档、兼容性及成本；记录实际锁定版本。
