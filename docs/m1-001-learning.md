## 1. 先看数据怎样流动

```mermaid
flowchart LR
    A[单一订单号] --> B[严格参数校验]
    B --> C[程序注入可信模拟身份]
    C --> D[工具权限与业务组检查]
    D --> E[虚构业务数据查询]
    E --> F[安全结果与版本证据]
```

业务组检查需要读取内部归属元数据；内部查到记录不代表可以把它返回给调用者。参数、身份或工具权限不合法时不访问数据源；跨组时可以在可信程序内部查归属，但返回结果不能暴露该记录或其存在性。

- `src/corpmind/contracts.py`：输入、可信身份、成功/失败结果和证据类型。两个工具共用 `OrderQuery`，模型参数只含 `order_id`。空白订单号与非字符串输入拒绝，额外身份、角色或确认字段拒绝。
- `src/corpmind/ports.py`：只读数据源接口和内部记录；`team_id` 留在可信程序内部。
- `src/corpmind/queries.py`：你的练习区。两个函数目前抛出 `NotImplementedError`，没有任何可用的调查工具或执行循环。
- `tests/fixtures/business.py`：固定时钟、四个虚构订单、模拟客服与可计数的数据源，不提供真实认证。

未来模型只提出工具名与参数，程序决定是否执行。当前没有模型调用、工具调度器、任务状态机或人工确认入口。不要从模型参数创建 `CallerContext`；本步只从测试夹具注入，不能据此声称已经完成登录或完整权限系统。

## 2. 当前只做练习1：成功查询订单

打开 `get_order` 和 `tests/test_order_exercise.py`。先读测试，再动手实现。当前用例已经提供可信客服 A 和 `ORDER-A-001`，目标是理解一次查询怎样变成可核对的结果。

可用的积木：

- `OrderQuery.model_validate(raw_args)`：得到经校验的订单号。
- `context`：程序注入的身份；`source.read_order(order_id)`：读取内部订单记录，可能返回 `None`。
- `record.team_id` 与 `context.team_id`：用于业务组校验。当前练习不涉及任务所有权；同组客服 A2 可以查询组 A 订单，但未来不能读取 A 的私有任务。
- `record.data`：可返回的订单事实，不包含业务组字段。
- `clock()`：查询观察时间；同一次结果与证据使用同一观察时间。
- `EvidenceRef` 与 `ToolSuccess`：组装版本证据和结果，沿用传入的 `request_id`。

成功标准：订单为 `ORDER-A-001`，状态为 `delivered`，物流标识为 `LOG-A-001`，记录版本为 1；只读一次订单，不查物流。证据种类为 `order`，记录 ID、版本与返回数据一致，观察时间来自固定时钟。`delivered` 表示系统记录签收，不能据此认定客户本人收到或包裹丢失。

默认检查只覆盖骨架。显式启用练习的命令见 [环境与验证记录](m1-001-validation.md)。函数未实现时该用例应当失败；不通过 `skip`、`xfail` 或返回硬编码订单来把练习变绿。完成后先解释代码与测试结果，再进入下一轮。

## 3. 后续逐轮加分支

以下是练习顺序，不要求本轮一次完成，也未声称已经运行。

| 轮次 | 动手内容 | 检查方法 |
| --- | --- | --- |
| 2 | 订单不存在、参数错误、无身份、无工具权限、跨组 | 不存在与跨组统一 `RESOURCE_UNAVAILABLE`/“资源不可用”；无效参数、无身份和工具禁用的数据源调用次数为 0；跨组返回值无原始记录、版本证据或存在性线索 |
| 3 | 物流成功查询 | 输入仍是 `order_id`；先查并授权订单，再查物流，校验物流所属组、订单号及关联物流标识；直接调用也不能绕过授权 |
| 4 | 物流缺失、关联冲突、跨组 | 缺失或不匹配时返回统一不可用结果，不拼凑轨迹；跨组订单应在物流读取前被拦截 |
| 5 | 受控超时、服务不可用 | 使用故障队列触发异常；转换为安全错误，不返回异常原文、数据或成功证据 |
| 6 | 调用方最多一次只读重试 | 先手工测试“超时后成功”和“连续超时”；两者最多两次尝试，不可重试错误只尝试一次。重试调用方仍由你编写，完整运行额度与核心循环留待后续 |

每轮只增加当前需要的测试。除首个成功用例外，目前没有写出其余查询练习测试；不能把骨架的参数类型测试理解为查询入口已经做了参数拦截。

后续错误约定如下，作为本步教学契约，不改变既有业务规则：

| 条件 | code / message | retryable |
| --- | --- | --- |
| 参数校验失败 | `INVALID_ARGUMENT` / 参数无效 | false |
| 没有可信身份 | `UNAUTHENTICATED` / 身份不可用 | false |
| 当前工具不在可信身份的允许集合 | `TOOL_NOT_ALLOWED` / 工具不可用 | false |
| 记录不存在、跨组或关联记录不一致 | `RESOURCE_UNAVAILABLE` / 资源不可用 | false |
| 模拟 `TimeoutError` | `TIMEOUT` / 查询超时 | true |
| 模拟 `ConnectionError` | `SERVICE_UNAVAILABLE` / 服务暂不可用 | true |

失败统一用 `ToolFailure`：没有 `data`，`evidence_refs` 为空；不直接返回 `str(exception)` 或 Pydantic 的详细错误内容。每个查询函数只做一次尝试，不偷偷重试。程序错误不伪装成业务记录不存在。
