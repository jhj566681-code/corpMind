# corpMind 测试与评测计划

版本：v0.2-draft。日期：2026-10-26。状态：业务验收与评测设计初稿；M1-001已提供可执行骨架检查和首个待完成练习，尚无完整业务验收结果或80条数据集。

对齐需求基线：v0.2（G0 已评审，见 [评审记录](g0-review.md)）。AC-01～AC-20为已确认需求的验收设计，以下状态及工单数量均是预期，不是执行结果。

## 1. 测试范围与方法

- 单元：业务规则、时间计算、参数、授权、索引、引用、状态转换和幂等。
- 契约：API与工具输入输出、错误代码、模型适配器、MCP与进程内工具一致性。
- 集成：临时SQLite、固定业务记录、模拟模型与故障注入；覆盖完整调查和确认写入。
- 端到端：使用客服和管理员账号，在界面完成导入、调查、确认、查看及取消。
- 效果评测：固定资料、时钟、模型、提示词及方案，核对事实、引用、工具行为与最终业务状态。

每个自动测试独立建临时数据并清理；不使用开发者真实资料，不需要云端密钥。付费模型的烟雾测试单独启用，记录次数与用量。

当前M1-001只使用独立内存夹具：默认检查契约约束、固定资料与受控故障；首个查询用例标记exercise并需显式启用，函数未实现时预期失败，不使用xfail掩盖。剩余业务与失败分支按 [学习指南](m1-001-learning.md) 逐轮补充，实际结果见 [验证记录](m1-001-validation.md)。骨架通过不代表FR-001、FR-005或AC-07、AC-15、AC-16完整通过。

### 关键验收细则

下列均是独立测试设计，不代表已执行；每项明确输入、状态和数据副作用，不以模型自评作为通过依据。

- AC-04：缺少订单号时追问“请提供订单号”，不调用订单或物流工具；同时提供ORDER-A-001和ORDER-A-002时，请客服选择本次调查哪一单。回复ORDER-A-001后在同一任务继续，仅查询所选订单，未确认前零工单。
- AC-05：有效客服凭证登录后读取当前身份及本人授权资源；错误凭证、未登录和已注销会话分别独立验证401。跨组订单、政策、原文及MCP查询返回统一不可用信息，模型输入、响应、事件和日志中均无受限正文、标题或存在性泄露。
- AC-06：使用A2访问A的任务、工单、笔记和事件，再反向检查；每次应拒绝，同时验证A2可以访问本人资源，排除仅靠业务组检查或全部拒绝的假通过。B与知识管理员另行执行非所有者访问；笔记隔离不改变管理员维护虚构历史案例的职责。
- AC-08：对尚未创建工单的当前方案分别输入“好的”“已核实仍未找到”、暂不回复、或让模型直接请求写工具，均不构成按钮确认，零工单；输入“先别创建，我再问问客户”时保持awaiting_confirmation；输入“方案不对，先不要创建”时立即使旧方案不可确认，进入追问并按需要awaiting_input，补齐后展示新版本且仍需按钮确认；通过取消入口明确取消调查时cancelled。旧按钮或直接确认请求均不能绕过服务端校验。
- AC-13：对文本型PDF、TXT和粘贴文本分别验证管理员可看到解析预览，文档ID、版本、位置及授权范围可核对，授权客服可检索对应原文；普通客服不能导入。解析长度或文件大小上限采用测试配置，分别检查恰好上限与超过上限，不在G0虚构已验证的解析能力。
- AC-14：在相同授权范围重复导入相同规范化内容返回已有记录；管理员更新后只检索有效版本，删除或收回权限后新请求不可检索、读取受限原文；旧引用标记过期、删除或不可用，待确认方案重新校验，工单不因资料修改自动创建。
